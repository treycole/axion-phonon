MnBi₂Te₄ calculation walkthrough

Every step from a crystal structure to ∂θ/∂Q: what it computes, where it runs, what the job script does, what the code does, how long it takes, and where its output sits in the new layout. Numbers are from the production runs (base 214290/214300, pattern 3 at Q = 0.01 Å). State of 30 Oct 2026.

The whole chain

For each structure (the base, and each displaced structure such as T2-_p3_Q0.01), steps 1–4 are DFT and run once. Steps 5–8 run once per window (the energy range the Wannier functions are built from), for a base/structure pair.

Each step folder holds the inputs, NOTE (what, when, job number), OK (job number) and out/ (everything the job produced). The pipeline scripts are in analysis/pipeline/; the cluster copy is /mnt/wkdk/bc889/axion/code/2026-10-29/pipeline/.

How every step is run

  1. login node Edit the settings block at the top of the step script (structure, mesh, window), run it with bash 5_wannier.sh.
  2. The script checks: the binaries' md5 (pw.x db4b99b4, pw2wannier90.x 8f5368ba, wannier90.x 26c8b506), the pseudopotentials and the code; that the steps it needs have OK and have left the queue; the inputs (k counts, window edges). Any failure stops it before anything is submitted.
  3. It writes send_job.sh in the step folder and submits it with qsub. Nothing is queued behind another job.
  4. cluster job The job starts in node scratch (/scratch/<job>bc889), copies its inputs there and checks them, runs, writes OK or FAIL into the step folder, exits 1 on failure. The cluster then copies scratch back to <step folder>/<job>bc889/; the next step renames that to out/ when it first reads it.

Every job script starts with the same header (queue, slots, memory, wall time, modules, and three helpers):

#!/bin/bash

#$ -pe orte_one 64          # slots (cores on one node)

PAW overlaps between the displaced structure and the base

cluster jobdisplaced structures only
Code
Ours: analysis/pipeline/overlap.py, calling axion_phonon.paw (readers in axion_phonon.io.qe)
What
Omn(k) = ⟨ψstructuremk|S|ψbasenk⟩, a 240 × 240 matrix at each of the 512 k
Why
The displaced structure's Wannier functions are built from the base's Wannier functions as trial orbitals, unshifted. Then the two Wannier gauges match and the parametric connection Λ vanishes exactly at O(Q), so the frozen-gauge c₂ (step 6) is exact. Projecting needs this overlap between two different crystals. With PAW the inner product carries the metric S = 1 + Σ |β⟩ q ⟨β| on each structure's own atoms; the old Julia code left S out (bug #23)
Output
overlap_k8/out/chunks/chunk_0000.npz … chunk_0007.npz: each holds its k points, their k vectors and O
Resources
48 cores; 512 k in about 11 min

What the code does at each k

  1. Read wfc<k>.dat of both structures: plane-wave coefficients of 240 bands, two spin components.
  2. Plane-wave part: match the G vectors of the two files, take ⟨ψs|ψb⟩ over common G.
  3. PAW part: project both on the β functions of each structure's atoms (476 projectors), add ⟨ψs|βs⟩ q ⟨βb|ψb⟩ with the small atomic displacement handled exactly.
  4. Check once: each structure's own states are S-orthonormal (production: 1.7e-14).
Why 8 slices?

Each k is independent and takes about 10 s (pattern 3: 64 k in 11 min per slice). In one process the 512 k take about 85 min. The job runs 8 copies of overlap.py side by side, each on every 8th k (k = 1, 9, 17, … for slice 1), with 6 threads each: 8 × 6 = the 48 cores of one node, done in about 11 min. The number 8 is only for speed; the result is identical, and step 5 reads all 8 chunks back into one 512 × 240 × 240 array. (For pattern 3 at 8³ the slices ran as 8 separate jobs from an older script; their chunks are now gathered in overlap_k8/out/. The 10³ overlaps ran as one job: 1,000 k in 45 min.)

wannier90: Wannier functions for one window

login nodecluster job
Login node
Set dis_froz_max and dis_win_max in the .win; check that both edges are at least 5 meV from every NSCF eigenvalue at every k, and that the displaced structure has the same number of bands below each edge at every k as the base (else one structure's Wannier functions would be built from a different set of states)
Program
wannier90.x 4.0.3 (26c8b506), one process (mpirun -np 1), projection only: num_iter = 0, dis_num_iter = 0
What
From the 240 bands, the 116-dimensional subspace and its 116 Wannier functions: V(k) = Udis(k) U(k), 240 × 116 at each k. The frozen window (below dis_froz_max) is kept exactly; above it, up to dis_win_max, the states are chosen by projection on the trial orbitals
Trial orbitals
Base: the atomic orbitals (the .amn from step 3). Displaced structure: the base's Wannier functions for the same window, A(k) = O(k) Vbase(k) (analysis/pipeline/mode_amn.py, from step 4 and the base's .chk)
Output
windows/<window>_k8/<structure>/out/MnBi2Te4.chk (V(k), the overlaps M rotated to the Wannier gauge, the centres), .wout, and the .eig, .win, .nnkp step 6 reads
Resources
8 cores reserved for memory (28.8 GB); base 21 min, pattern 3 44 min (the .amn step adds ~20 min)
cp $SGE_O_WORKDIR/{MnBi2Te4.win, MnBi2Te4.nnkp} .
get pw2wannier_k8/out MnBi2Te4.mmn;  get pw2wannier_k8/out MnBi2Te4.eig
base:      get pw2wannier_k8/out MnBi2Te4.amn
pattern:   copy overlap_k8/out/chunks/*  and  windows/<window>/base/out/MnBi2Te4.chk  into scratch
           python mode_amn.py              # A(k) = O(k) V_base(k) -> MnBi2Te4.amn
mpirun -np 1 wannier90.x MnBi2Te4 > MnBi2Te4.wout
'All done' in .wout and .chk exists || fail;  delete the scratch copies of .mmn, overlaps
ok

c₂: the axion-response density on the tube k points

login node10 cluster jobs
Login node
Write the k list (axion_phonon.tube.klist(16, 4, 3, 8), 7,928 points) and c2.py with the settings (n_occ = 82, Q = 0.01 Å); submit 10 jobs with qsub -v TASK=1 … TASK=10
Code
Ours: analysis/pipeline/c2.py → axion_phonon.io.wannier90, .wannier, .curvature, .axion
Output
dtheta_<structure>/c2/out_<task>/chunks/chunk_<task-1>.npz: the task's k indices, c₂ at both ends, the direct gap
Resources
8 cores each; 218727: 793 k in 27 min, of which ~3 min building the models

What the code does

  1. Read both Wannier runs (read_run): V(k), the band energies, the overlaps M(k, b) in the Wannier gauge (1.2 GB), the k mesh, the neighbours b, the lattice, the Wannier centres and the atoms.
  2. Common positions (pair_models): each base Wannier centre is replaced by its nearest atom; these 116 positions are used for both structures (one embedding τ for both ends of the finite difference).
  3. H(R) (hamiltonian_R): H(R) = (1/Nk) Σk e−ik·R V(k)† E(k) V(k), at full precision from the .chk and .eig, one R per aliasing class of the 8³ mesh, then each matrix element moved to the image of R closest to its two orbitals (fold).
  4. A(R) (position_matrix_R): the Wannier position matrix ⟨0m|r|Rn⟩ from the overlaps M by Wannier90's translation-invariant formula, folded on the same positions.
  5. Models (tb_model): two PythTB models carrying H(R) and A(R).
  6. At each k of the task: H(k), ∂H/∂k, A(k) and its curl for both structures (curvature.fields); the fourth direction β from the finite difference between the structures, ∂H/∂β = (Hstructure − Hbase)/Q and the same for A (axion.beta_terms); diagonalise; the non-Abelian Berry curvature Ω of the 82 occupied bands in the four directions (kx, ky, kz, β), as internal + cross + external parts (curvature.connection, omega); c₂ = (1/16π) εμνρσ Tr[Ωμν Ωρσ] (axion.c2_density).
  7. Two ends: the spatial fields at the base (β = 0) and at the displaced structure (β = Q) give two estimates of the same derivative, the "base end" and "structure end" (they differ at O(Q)).
Why a tube, and why 7,928 k?

c₂ is ~10³ near the line kx = ky = 0 through Γ (along kz), where the direct gap is only ~0.19 eV, and small elsewhere. The list is a 16 × 16 grid in each of 8 planes along that line, with every cell within 3 cells of the line replaced by a 4 × 4 finer grid. Converged to ~0.1% (studies/tube_convergence).

Why 10 outputs?

One job holding both models needs ~25 GB, so it reserves a whole 8-core slot of memory, and does about 0.3 k points per second: the 7,928 points would take ~4.5 h in one job. Split 10 ways (task i takes points i, i+10, i+20, …, so each task samples the whole tube and they finish together), the 10 jobs run on 10 nodes at once and finish in ~27 min. They are separate jobs, not an SGE array, at the admin's request. 10 is only for speed: the sum in step 7 uses all 7,928 values exactly once.

cp $SGE_O_WORKDIR/{c2.py, klist.npz} .
for f in .chk .eig .win .nnkp:  get windows/<w>/base/out MnBi2Te4$f  -> base/
                                get windows/<w>/<structure>/out MnBi2Te4$f -> mode/
python c2.py      # TASK = 1..10 from qsub -v; writes chunks/chunk_<TASK-1>.npz
rm -rf base mode;  chunk written || fail
ok    # -> c2/OK_<TASK>
